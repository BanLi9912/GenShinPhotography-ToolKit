# 原摄工具箱 · 拖拽采集（浏览器扩展）

把网页上的图片**拖进浮层**，直接落盘到图库正在浏览的目录（或其真实子目录）——模仿 Eagle 的采集交互，但**只落盘、不动索引**：保存完回工具箱点「重新扫描」，新图才按现有流程进入索引与分析。

- 工具箱侧接收端：`web/src/modules/library/collector/`（`types.ts` 协议真值 / `receiver.ts` FSA 操作 / `bridge.ts` 页面桥接）
- 本目录是**无框架本地 JS**（MV3，service worker + content scripts），构建产物由 `web/scripts/build-collector.mjs` 校验并生成 `tokens.js`
- 协议：命名空间 `ystk-collector`、版本 `1`；工具箱页面与扩展之间只用 `window.postMessage` + `chrome.runtime` 转发，不引入第三方库

## 一、安装（手动，一次性）

没有打包成 `.crx`，也不自动安装（扩展必须由用户手动加载）：

1. 先在工具箱仓库跑一次构建（生成 `tokens.js`，否则扩展加载会报缺文件）：

   ```bash
   export PATH="/d/Project/YuanSheToolKit/.tools/node:$PATH" && cd /d/Project/YuanSheToolKit/web && npm run build
   # 只重建扩展部分：npm run build:collector
   ```

2. 浏览器地址栏进入扩展管理页：Chrome / Edge 都是 `chrome://extensions`（Edge 则是 `edge://extensions`），打开右上角**开发者模式**。
3. 点「加载已解压的扩展程序」，选择本目录 `web/extensions/collector`（选到 `manifest.json` 所在层）。
4. 列表里出现「原摄工具箱 · 拖拽采集」即成功；点工具栏图标能看到弹窗面板。

更新流程：改了本目录任何 `.js` 或 `tokens.css` 之后，先跑 `npm run build:collector`，再在扩展管理页点该扩展的**刷新**按钮（改了 `manifest.json` 必须刷新；只改 content script 也要刷新才会重新注入）。已经打开的网页需要**重新加载**，旧页面里的 content script 不会自动换新。

## 二、使用前准备

1. 用官方入口起 dev server：`scripts/start-web.bat`（不要在扩展里配端口，写死的白名单只有 `http://localhost:5173` 与 `http://127.0.0.1:5173`）。
2. 打开工具箱的图库页 `http://localhost:5173/library`，绑定/选择一个图库，进入就绪态。
3. 想让扩展知道「现在在看哪个目录」，**工具箱必须停在该图库页**：扩展通过页面里的接收端读取当前图库名与浏览目录，工具箱关掉或在别的页面时，拖图会提示「没有找到工具箱页面」。

> `localhost:5173` 与 `127.0.0.1:5173` 在浏览器眼里是**两个不同的站点**，FSA 目录授权互不通用。换地址访问要重新授权图库目录；扩展本身两端都支持。

## 三、怎么用

1. 在任意网页（`http://` / `https://`）上按住一张图片拖一下——**你开始拖的那张图旁边**会弹出采集浮卡（Eagle 那种两栏卡片：左栏是当前目录的大投放区，右栏是子目录列表）。浮卡在本次拖动期间固定不动、不跟鼠标跑；拖动起点靠右/靠下放不下时，自动翻到图片左边/上方，始终留在视口内。
2. 卡片里两类区域，**框型就是图例**（底栏那行小字）：
   - **虚线框 = 投放区**：左栏那一大块（当前目录，角上有「投放区」小标）+ 右栏每一行子目录。拖进去松手 → 直接保存到该目录；
   - **点线框 = 悬停区**：「返回上级」和每行的「展开下级」。拖图停在上方 **0.5 秒**才生效（进下级 / 返上一级），松手仍落到该行对应的目录，不会因为想展开而换掉投放目标。
3. 拖到某块区域上时，该块从虚线变**实心高亮**，状态行同时显示完整落点（例如「松开保存到 参考图库/人像」）。
4. 松手即落盘。状态行给出落点，例如「已保存到 参考图库/人像」。
5. 回工具箱点**重新扫描**，新图才出现在网格里（保存本身不写索引、不分析、不刷新）。

**不压暗页面、不吃页面事件**：浮卡之外的地方完全透传（宿主 `pointer-events: none`，只有卡片本身 `auto`），网页自己的拖拽、松手、点选一律照旧；在卡片空白处松手 = 取消这次采集。

**提示态**（连不上工具箱 / 采集关闭 / 上一张还在保存 / 目标被拦）：在同一个位置（拖动起点旁）弹一张提示卡，不画虚线框、不显示图例，此时任何区域都不可投。

文件名默认取 `alt / URL 末段 / 页面标题` 的可读主干 + 随机后缀，同名不会覆盖已存在的文件。格式不做 canvas 重编码，原字节原样写入（jpg/jpeg/png/webp/gif/bmp/avif，按文件签名判定，上限 32 MiB）。

拖出浮卡松手、按 Esc、拖文字/链接、拖进网页自己的投放区：都不保存，也不拦截网页原有拖拽。

> 改过浮层（`overlay.js`）或主题令牌后：`npm run build:collector` → 扩展管理页点该扩展的**刷新** → **重载网页**，三步都要，否则旧 content script 还在跑。

## 四、工具栏弹窗

- **采集开关**：关掉后拖图不再弹浮层（状态提示会告诉你已关闭）。
- **接收端**：显示当前连接的工具箱标签页与浏览目录；同时打开多个工具箱标签页时列出候选，「多个工具箱标签页」时**不猜**，必须手动选定一个。
- **上一次采集**：保存中 / 已保存 / 结果未确认 / 失败 + 时间。出现「结果未确认」表示提交后连接断了，**不会自动重试**——先去目标目录看一眼再决定要不要重拖。

## 五、离线自测页

`fixtures/drag-demo.html` 是一个不联网的小页面（用 canvas 现画三张 PNG，`data:` URL），用来在不起任何外部网站的情况下验证拖拽链路：

```bash
# 用你自己的浏览器直接打开本文件即可
web/extensions/collector/fixtures/drag-demo.html
```

> 注意：`file://` 页面不在 content script 的注入范围（`http/https` 才算），所以拿它只在开发时配合「临时把 host_permissions 放宽到 `file:///*`」用；不想改 manifest 就用任意 `http(s)` 网页实测。

## 六、权限与安全边界

| 项 | 值 | 说明 |
|---|---|---|
| permissions | `storage`、`tabs` | 存开关/接收端状态；`tabs` 只用于定位工具箱标签页与 url 判定 |
| host_permissions | `http://*/*`、`https://*/*` | content script 要注入才能看到拖拽；**不含** `<all_urls>`、`file://`、`chrome://` |
| 未申请 | `downloads`、`nativeMessaging`、`debugger`、`cookies`、`externally_connectable` | 采集走页面内 FSA 写入，不下载、不碰 cookie、不与本机进程通信 |

- 抓图用 `fetch(..., { credentials: "omit" })`：不带登录状态，取不到就是取不到，**不会**把「登录页 HTML」当图片存下来（服务端返回非图片 Content-Type 时直接报错）。
- 工具箱侧只接受白名单 origin + 已握手实例 + 顶层 frame 的消息；采集写入走的目录句柄拿到了 `readwrite` 授权才算就绪，权限掉了就报「目录权限已失效」，不会退回根目录写。
- 一次只允许一个活跃保存任务：上一张还在写时再拖会提示等待，**不静默丢图**。

## 七、故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 拖图没有任何反应 | 扩展没启用 / 页面是 `file://` 或 `chrome://` / 采集开关关着；先看弹窗里的「接收端」状态 |
| 浮卡是**一堆没样式的纯文字**贴在网页左上角 | 2026-11-13 之前的老版本有 CSS 选择器括号 bug（`[data-theme="x"]` 改写后少了 `)`），整张样式表被吞掉。走「`npm run build:collector` → 扩展刷新 → **重载网页**」三步换成新版本；该 bug 现在由构建期的括号配对自检拦截 |
| 浮卡出来了，但看不到虚线/点线框 | 网页里还是**旧的 content script**：扩展刷新后必须**重载网页**；另外「提示态」（没连上/被拦）本来就不画框 |
| 浮卡跑到屏幕另一边 / 挡住图片 | 位置按拖动起点算：右/下放不下就翻到左边/上方，再夹进视口。换一张图重拖即可 |
| 能看到浮卡但拖进去不高亮 | 同上（旧脚本），或当前是提示态：看状态行写了什么原因 |
| 「没有找到工具箱页面」 | 工具箱没打开，或没停在 `/library`；打开后拖图会重新握手 |
| 「多个工具箱标签页」 | 关掉多余的 `/library` 标签页，或在弹窗里选定一个 |
| 「目录权限已失效」 | 浏览器重启或清站点数据后 FSA 授权丢失：回工具箱重新授权图库目录 |
| 「目标已变化」（旧浮层失效） | 换图库/换目录/权限变动会让 `contextVersion` 递增；重新拖一次即可 |
| 「取图超时（20 秒）」/「不是图片」 | 原图站有防盗链或需要登录；扩展不带 cookie，属预期拒绝 |
| 保存成功但图库里看不到 | 预期行为：回工具箱点「重新扫描」 |
| 弹窗显示「扩展刚从后台唤醒」 | worker 休眠后重新握手，属正常；再拖一次即可 |

## 八、文件清单

| 文件 | 作用 |
|---|---|
| `manifest.json` | MV3 声明：两条 content script（工具箱白名单 / 普通网页）、service worker、弹窗 |
| `background.js` | 路由与状态机：角色判定、接收端发现与握手、抓图、分块传输、单活跃保存、`chrome.storage.session` 恢复 |
| `toolkit-bridge.js` | 只在工具箱页面：`chrome.runtime` ↔ `window.postMessage` 双向转发、请求超时与重发 |
| `content.js` | 只在普通网页：`dragstart` 识别图片 → 建会话 → 开浮层 → 提交保存 → 跟随 `contextVersion` 校验 |
| `overlay.js` | 浮卡视图（Shadow DOM 隔离样式）：Eagle 式两栏卡片（左投放区 / 右子目录列表）、落在拖动起点旁、投放区/悬停区范围标注与图例、500ms 悬停下钻、`collect`/`notice` 两模式；导出 `toHostCss`/`COMPONENT_CSS` 供构建期样式自检 |
| `popup.html` / `popup.js` / `popup.css` | 工具栏弹窗：开关、接收端与候选、上一次采集状态 |
| `tokens.js` | **生成物**（勿手改）：从 `src/styles/tokens.css` 抽出变量，供浮层与弹窗复用同一套设计令牌 |
| `fixtures/drag-demo.html` / `drag-demo.js` | 离线自测页（canvas 现画 PNG，不联网） |
